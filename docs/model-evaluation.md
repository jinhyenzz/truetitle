## 입력 처리와 한계

1. API가 제목 1~300자, 본문 1~50,000자를 검사하고 앞뒤 공백을 제거한다. 공백뿐인 값도 거부한다.
2. 제목의 직선·굽은 큰따옴표 중 짝이 확인되는 구간을 `“ ”`로 통일한다. 단독 부호, 줄을 넘는 쌍, 작은따옴표와 본문은 보존한다. 중첩 인용 전체를 해석하는 문법 분석기는 아니다.
3. 토크나이저에 제목과 본문을 두 입력으로 전달한다. API는 합계 최대 128토큰에서 양쪽 입력을 안전하게 자른다. 학습 당시에는 본문만 자르는 방식을 사용했으므로 매우 긴 제목은 학습 조건과 다를 수 있다.
4. 모델의 클래스 0 출력에 100을 곱하고 소수점 한 자리로 표시한다. 50점 이상이면 낚시성 분류이며, 표시는 20·40·60·80 경계의 5구간으로 나눈다.
5. 참고 표현과 유사도는 원래 제목·전체 본문의 단어 포함·한국어 표면 형태를 비교한다. 모델에 실제로 영향을 준 이유를 추적한 설명은 아니다.

신규 평가 10건의 본문은 193~2,498토큰이었다. 모두 모델의 합계 128토큰 입력 한도보다 길다. 뒷부분의 반론·조건·해명을 모델이 보지 못할 수 있다. 입력 길이를 늘리는 일은 속도·메모리와 성능을 다시 비교해야 하므로 이번 변경에서는 하지 않았다.

## 재현 명령

기존 가상환경과 모델이 있는 프로젝트 루트에서 실행한다. 새 보고서 경로를 지정해야 하며 기존 파일을 덮어쓰지 않는다. CPU 스레드 2개로 제한하고 50건마다 진행 상황을 출력한다. 200건 비교는 이 실행에서 모델 로딩·추론을 포함해 약 43초였다(프로세스 시작·라이브러리 import 시간 제외).

```powershell

```

## 설명할 수 있어야 하는 설계 결정

- 중복된 본문이 학습과 검증에 같이 있으면 외운 내용을 맞혀 평가가 좋아 보일 수 있어 분리했다.
- TF-IDF 베이스라인으로 비교 기준을 만들고 제목·본문을 함께 입력받는 Transformer로 확장했다.
- 모델을 학습한 결과는 가중치 파일로 저장되며 API가 로딩해 재사용한다. 요청마다 새로 학습하지 않는다.
- 문장부호만 바꾼 통제 비교로 입력 표기에 민감한 동작을 찾았다. 보정 후에는 좋아진 사례뿐 아니라 놓친 사례도 기록했다.
- 단위 테스트는 코드 동작을, 별도 평가 표본은 모델 판단을 확인한다. 둘을 같은 정확도 증명으로 사용하지 않는다.
